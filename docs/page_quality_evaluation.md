# PDF → Page 链路小规模质量抽检

## 1. 评估目的

当前链路已能按页选择 Text/OCR 并输出统一 Page，但 `有效字符 >= 20` 只判断字符
数量，不能证明正文可读。本次在 Clause Parser 前抽检真实 Page，识别乱码、伪文本、
OCR 错误及结构损失。评估不修改 Parser，也不把小样本统计外推为全库准确率。

## 2. 样本构成

共25页，明确选择能够覆盖正常正文、封面、条款、表格、流程图和已知乱码边界的
真实页面：

| 来源类型 | Text Page | OCR Page | 合计 |
| --- | ---: | ---: | ---: |
| text PDF | 6 | 0 | 6 |
| no_usable_text PDF | 0 | 8 | 8 |
| mixed PDF | 6 | 5 | 11 |
| 合计 | 12 | 13 | 25 |

Text PDF 样本来自3份不同 PDF；no_usable_text 样本覆盖封面、目录、连续正文、数字、
条款和球罐图示；mixed 样本覆盖表格、附录文字及流程图。该抽样有意提高风险页
占比，用于发现失败模式，不代表7454页总体质量分布。

## 3. 质量标准与复核依据

- `good`：主体完整可读，可以直接用于 Clause 切分；允许少量换行、页眉页脚或
  非关键标点差异。
- `acceptable`：主体可理解，但存在 OCR 错字、编号风险、表格损失或少量噪声，
  进入后续处理时需要保留风险。
- `bad`：大面积乱码、主体缺失、只剩伪文本，或阅读顺序/二维关系严重丢失，
  不适合直接进入 Clause Parser。

25页均由 Codex 逐页对照原 PDF 的120 DPI页面图像、完整 Page JSONL 与短 preview
后标注。它是可复核的人工视觉工程判断，不是用户确认的 Gold，也不是程序根据
字符比例自动生成的标签。

## 5. Text 路由问题

Text 路径发现两种重要失败模式：

1. 字符很多但正文乱码。mixed PDF 的119、120、121、149页均达到20字符，却包含
   大量异常拉丁字符和不可读映射；原 PDF 表格或正文实际清晰。
2. 字符刚过阈值但只是伪文本。GB/T 3274封面有效字符22个，Page 仅保留“内部收藏”
   水印；mixed 第144、145页分别为22、23个有效字符，但流程图主体没有进入 Text。

因此有效字符数量不等于正文可用性。中文比例也只能辅助观察：第149页有效字符
199个，但中文比例仅约10.1%，人工对照确认其主体不可读；另一方面，第144、145页
中文比例为100%，仍然只是很短的伪文本，说明单一比例也不能独立解决问题。

## 6. OCR 问题

- 中文：连续中文正文整体可读，普通段落明显优于原扫描文本层。
- 数字：`70%`、`47018`、`2017` 等多数可识别，但流程图标引序号容易混合、串联
  或产生无意义数字序列。
- 条款号：抽样正文中的 `7.2.3`、`7.3`、`8` 基本正确，本样本未确认独立的
  `clause_number_error`；这不代表全库条款号无风险。
- 标准号：`NB/T 47018.1—2017` 主体通常可读，但破折号、短横线与汉字“一”存在
  混淆。
- 噪声与结构：水印、页码可能进入结果；表格和流程图的二维对应关系无法由当前
  换行文本恢复，是 OCR bad 页的主要原因。

## 7. 典型案例

### good Text：PQ-001

```text
《移动式压力容器安全技术监察规程》(TSG R0005-2011)
第1号修改单……1.3.1(3)修改为……450L……150L……3000L
```

正文、条款和关键数字与原页整体一致。

### bad Text：PQ-017

```text
î　ï　犅
（ðQ2）
òóÜôõöYZ%&'()*……
```

原页是清晰的附录 B 说明文字，但字符数达到51后被路由为 Text，主体不可读。

### acceptable OCR：PQ-010

```text
NB/T47018.1—2017
承压设备用焊接材料订货技术条件
第1部分：采购通则
1范围……2规范性引用文件……3.1……3.5……
```

主体条款可读，但标准号连接符等存在少量混淆。

### bad/复杂 OCR：PQ-018

```text
GB/T30579—2022
减压轻蜡油
减压重蜡油
9①……②99①……
```

原页是横向复杂流程图。OCR 能识别部分设备名，却不能保存管线连接、标引序号与
设备之间的二维关系，因此不适合直接进入 Clause Parser。

## 8. 对20字符规则及 Clause Parser 的判断

当前 `有效字符 >= 20 → text` **不足以作为正式路由规则**。主要失败模式是：

- 字符映射乱码仍会贡献大量中文、英文或数字计数；
- 水印或收藏标记可以单独超过阈值；
- 表格、流程图可能只有少量伪文本达到阈值，而主体实际位于图像中；
- 字符数量不评价语言可读性、正文覆盖率或版面类型。

工程结论为：当前 Page 数据质量**不适合无条件直接进入 Clause Parser**。普通正文
Text 和部分 OCR 正文已具备可用性，但 bad Page 缺少可供下游识别的质量信号；直接
切分会把乱码和伪文本当成法规内容。Clause Parser 前应先建立文本层质量判定
baseline，并据此改进 Text/OCR 路由依据。

## 9. 人工复核方法

1. 打开 `data_processed/evaluation/page_quality_sample.json` 查看25条完整抽检记录。
2. 使用 `relative_path` 和 `page_no` 定位原 PDF 页面。
3. 查看 `data_processed/evaluation/page_quality_images/` 中同 sample_id 的 PNG。
4. 对 bad Text 重点复核 PQ-005、PQ-015～PQ-017、PQ-020、PQ-021、PQ-025。
5. 对 OCR 数字与条款号重点复核 PQ-007～PQ-014；对流程图复核 PQ-018、PQ-019、
   PQ-022～PQ-024。
6. 标签元数据明确写有评审者和依据，并标记 `labels_are_user_confirmed=false`；
   它不是用户确认的 Gold，可由人工修改后重新
   汇总。
