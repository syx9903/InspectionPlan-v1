# OCR 单页最小实验与输出评估

## 1. 实验目的

TASK-002.2 发现 3772 页没有达到文本层可用 baseline。在实现整份 PDF OCR Parser 前，本实验先验证项目现有 RapidOCR 能否运行、中文法规页面是否基本可读、不同 DPI 的影响、原始返回结构和单页性能量级。

本实验只处理 3 个真实页面，每页比较 150、200、300 DPI，共执行 9 次 OCR，不修改 Page Schema，也不生成整份 PDF Page JSONL。

## 2. OCR 引擎

- 引擎：`rapidocr-onnxruntime 1.4.4`
- 推理运行时：`onnxruntime 1.28.0`
- PDF 渲染：`PyMuPDF 1.28.2`
- Python：3.12，Windows AMD64

RapidOCR 原生 ONNX Runtime 在受限沙箱内加载时报“拒绝访问”，在沙箱外使用同一虚拟环境可以正常导入和推理。没有安装或切换 PaddleOCR、Tesseract 等其他引擎。

## 3. 页面渲染方式

使用 PyMuPDF 将 1-based 页码转换为内部 0-based 索引，并按以下方式生成 RGB、无 alpha 的内存 PNG：

```text
zoom = dpi / 72
Pixmap = page.get_pixmap(Matrix(zoom, zoom), RGB, alpha=False)
Pixmap → PNG bytes → RapidOCR
```

实验比较 150、200、300 DPI。默认不保存页面图片；为人工对照只保留了三个样本的 200 DPI PNG，全部位于被 Git 忽略的 `data_processed/ocr_experiments/`。

## 6. OCR 原始输出结构

RapidOCR 1.4.4 返回：

```text
(result, elapse_list)
```

- `result` 每项为 `[bounding_box, text, confidence]`；
- `elapse_list` 依次记录检测、方向分类、识别阶段的内部耗时；
- 实验 JSON 将每一行规范化为 `box`、`text`、`confidence`。

真实简化示例：

```json
{
  "box": [[122.0, 138.0], [325.0, 134.0], [325.0, 160.0], [123.0, 164.0]],
  "text": "NB/T 47018.1-—2017",
  "confidence": 0.9232300139
}
```

每个 DPI 的完整原始行结果保存在：

```text
data_processed/ocr_experiments/<sample_id>_<dpi>dpi_raw_ocr.json
```

## 7. 正文拼接 baseline

当前只按 RapidOCR 返回顺序提取每行 `text`，使用换行拼接：

```text
OCR 行结果
→ 保持返回顺序
→ text 以换行连接
```

不进行双栏重排、图示标签归位、表格二维恢复、页眉页脚删除或 Clause 拼接。

## 8. OCR 典型问题

### 中文字符

- 连续中文正文总体可读，但存在个别姓名或低频字误识别。
- 图示中出现“桔瓣式”误为“桔舞式”、“上温带”误为“上湿带”、“下温带”误为“F温带”。

### 数字与标准号

- `8.2`、`9.1`、`9.2` 在 150/200 DPI 基本稳定。
- `NB/T 47018.1—2017` 中不同横线可能被识别成 `-—`、`一` 或其他连接符。
- `GB/T 1.1—2009` 等标准号中的横线同样存在混淆风险。

### 标点

- 中文/英文括号和列表符号存在不一致，如 `b)`、`b）` 或与正文拆成两行。
- 破折号、短横线和汉字“一”容易互相混淆。

### 页面结构

- 页码和“公众号/小程序”水印会进入 baseline 正文。
- 普通单栏正文的返回顺序基本符合阅读顺序。
- 图示页的标签按检测框顺序输出，无法表达标签与具体球罐图形的二维对应关系。
- 大面积印章会干扰检测；300 DPI 并不必然改善，样本 B 反而漏掉整行正文。

## 9. baseline 决定

当前选择：

```text
默认 DPI = 200
颜色空间 = RGB
alpha = false
输入 = 内存 PNG bytes
```

理由：

- 普通正文与 150/300 DPI 基本同等可读，平均行置信度略高；
- 条款编号页面在 200 DPI 保留了关键 `8.2/9.1/9.2`，300 DPI 出现整行漏识别；
- 相比 300 DPI，200 DPI 图像像素量和渲染成本明显更低；
- 150 DPI 在本小样本中已经可用，但 200 DPI 为小字号和后续更多页面留出适度分辨率余量。

这是基于 3 页、9 次实验的当前 baseline，不是最终最优参数。后续仍需在更多典型页面上人工评估，尤其关注法规数字和条款编号。

## 10. 性能概览

9 次小样本平均值：

```text
平均 render_ms = 170.3
平均 ocr_ms    = 2897.5
平均 total_ms  = 3067.8
```

耗时随页面文字密度变化明显：连续正文约 5 秒，图示页约 1.5 秒。以上不包含 OCR 模型初始化，且只反映当前机器和当前小样本。

## 11. 局限

- 没有逐字 Gold，不能计算正式准确率。
- 置信度高不代表数字、连接符或条款编号一定正确。
- 只测试 3 个页面，不能代表全部 3772 个不可用文本页。
- 当前未决定表格、双栏、印章和图示页面的结构恢复策略。
- 当前实验不会自动纠错，也不会将 OCR 结果转换为 Page。
